# LinguaTrail

Authenticated API prefix: `/api/v1/lingua`. See the LinguaTrail Swagger tag for all 12 operations. Published content only; user attempts and itinerary language overrides are personal, not shared group edits.

Apply `073_create_lingua_trail.sql` once after a database backup. Check `to_regclass('lingua.languages')` first; this migration deliberately fails rather than overwriting an existing deployment. No new environment variables or worker are required. Rebuild backend after merging; video worker is unchanged.

Ten language packs in `content/lingua` are DRAFTS. The migration seeds only draft language identities; language listing stays empty until reviewed content is explicitly published. Do not publish drafts merely to populate the UI. Follow `content/lingua/README.md` and its review checklist. Audio is optional and is not generated by this module.

Validation and release checks:

```sh
RUN_LINGUA_DB_TESTS=1 npm test -- --runInBand --watchman=false --coverage=false --reporters=default --testPathPatterns=lingua
```

The opt-in database suite starts a new local temporary PostgreSQL cluster, applies the actual migration against prerequisite fixture tables, and checks publication immutability, parallel attempt start, ownership, hidden answer keys, immutable answers, practice, scoring and retry behavior. It never uses UAT. HTTP tests use mocked authentication/service; service tests use mocked repositories. These tests do not constitute live Flutter/device verification.
